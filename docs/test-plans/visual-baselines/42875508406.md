## Assumed — ask

1. **No app change → no Cypress / API / e2e / axe rows.** Confirm VB-01–03 (run existing visual project against these baselines) is enough; do not expand to the full suite solely because snapshots live under `tests/`.
2. **Baselines are intentional oracles.** Confirm the committed Linux PNGs (from `visual-baselines` workflow / `--update-snapshots`) are the accepted look — triage should **not** regenerate them; failures are findings if the live UI no longer matches.
3. **“Plenty” / “few left” labels in test titles** are scenario names only. `APP-MAP.md` / `PlantCard` only document an **Out of stock** overlay at `stock === 0`; `slots/plant-card/` has no stock badge plugin. Confirm we do **not** assert a “few left” badge in pixels beyond what the PNG already encodes.
4. **Platform.** Snapshot filenames are `*-linux.png`. Confirm visual verification must run where Playwright resolves those baselines (Linux / CI), not a host that would look for a different OS suffix.
