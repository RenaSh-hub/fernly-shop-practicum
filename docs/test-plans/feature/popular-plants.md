# Test plan: feature/popular-plants

## Summary

Adds **Popular right now** on every plant page: `GET /api/popular` ranks plants by units sold in the last 30 days, and a plant-page slot renders `PopularList` (up to four links, current plant left out). Oracle: `docs/features/popular-plants.md` and OpenAPI (`PopularList` / `PopularPlant`); `docs/PRODUCT.md` accessibility (WCAG 2.1 AA) still applies to the plant page. Docs win over the code when they disagree. No money, privacy, or sign-in surface — ranking correctness, out-of-stock exclusion, and browse-time latency come first.

## Assumed — ask

1. **Units vs orders:** Feature doc requires units sold (workshop 40 → 40). Implementation adds `1` per sale row, ignoring `quantity`. Confirm T1 asserts units and treats order-counting as a finding.
2. **Out-of-stock filter:** Doc excludes stock 0; handler never filters on `stock`. Confirm T2/T8 fail if `pl-pilea` (stock 0) appears.
3. **Performance harness:** No load tool is in-repo. Confirm T4/T5 may use concurrent Playwright `request` (or equivalent) against the running API to measure p95 / failure rate, and that missing the 300 ms / zero-failure bar is a finding, not a skipped row.
4. **UI `limit=5`:** Slot requests five so the list can still show four after dropping `currentId`. Confirm that matches the “four plants” product rule (T6/T7), not a requirement that the API default alone drive the UI.
5. **PRODUCT.md** does not mention popular plants; **`docs/features/popular-plants.md`** (plus OpenAPI) is the behavior oracle for this feature. Confirm.
