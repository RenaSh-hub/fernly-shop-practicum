# Test plan: feature/back-in-stock

## Summary

Adds low-stock badges on plant cards and a guest email notify sign-up for out-of-stock plants: `POST /api/plants/{plantId}/notify`, `StockBadge` via the plant-card slot, and `NotifyForm` via the plant-page slot. Oracle: `docs/features/back-in-stock.md`, OpenAPI on the notify path, and `docs/PRODUCT.md` accessibility (WCAG 2.1 AA). Privacy (email collection) rows first. Docs win over the code when they disagree.

## Assumed — ask

1. **Email oracle vs Zod:** Feature doc requires a full address (`name@example.com`) and refuses `a@b` / `name@`. Implementation only checks `includes('@')`. Confirm tests assert the doc (treat weak validation as a finding).
2. **Duplicate subscribe:** Doc and OpenAPI require 409 `already_subscribed` / “You're already on the list” (case-insensitive). Handler always pushes with no duplicate check. Confirm T4/T10 assert the documented 409 behaviour.
3. **Stock 0 badge:** Doc: at 0 show only “Out of stock”, never “Only 0 left”. `StockBadge` returns `Only {stock} left` for any `stock <= 3`, including 0. Confirm T6/T8 fail and file a finding if “Only 0 left” appears.
4. **Badge placement:** Doc: with tags under the name; never covers photo or save. `StockBadge` CSS is `position: absolute; top/right` on a `position: relative` card (photo/save zone). Confirm T8 asserts under-name placement and flags overlay as a bug.
5. **Exact 409 copy:** Confirm the customer-visible string must be exactly `You're already on the list` (doc) even if the API currently omits that path.
6. **Client-side email checks:** `NotifyForm` uses `noValidate` and does not mirror full-address rules. Confirm invalid emails are allowed to hit the API and that refusal is asserted from API/UI error display (T7/T9/T10), not from HTML5 validation alone.
