# Test plan: feature/fernly-helper

## Summary

Adds **Ask Fernly**, a chat helper on every page (`HelperWidget` in `Layout`): `POST /api/helper/chat` returns a reply and optional tool call (`search_plants`, `open_plant`, `add_to_cart`, `care_tip`); the browser runs the tool. Oracle: `docs/features/fernly-helper.md` and `docs/PRODUCT.md` (cart auth, stock, catalog, WCAG 2.1 AA). Docs win over the code when they disagree. Money and sign-in rows first. No **How fast it must be** section — no k6 row.

## Assumed — ask

1. **Reliability measurement:** Confirm “≥9/10” is asserted with a fixed `HELPER_SEED` (deterministic) and/or N repeated calls counting correct tool/args — and that random quantity misses under no seed are findings against the doc.
2. **Pet-safe phrases:** Doc lists “safe for my cat”, “safe for dogs”, “pet-friendly”. Confirm tests require those to set `petSafe: true` even if the stand-in only matches a subset of phrases.
3. **Refusal copy vs API “Added” reply:** Doc forbids saying “Added” when cart refuses. Confirm UI must replace/suppress the API’s success-shaped reply when `POST /cart/lines` fails (auth/stock), and that showing “Added” after a failed POST is a finding.
4. **Size on cart POST:** Confirm `add_to_cart` must send the tool’s `size` (S/M/L) to `/cart/lines`; hard-coding `S` in the widget is a bug to report, not expected behaviour.
5. **Off-catalog reply:** Confirm inventing a name/price for an unsold plant fails T4/T9; the required customer message is that the shop doesn’t sell it.
6. **`care_tip` client behaviour:** Tool is listed for shop data replies; confirm browser may no-op navigation for `care_tip` as long as the reply text matches catalog care/light/petSafe (and wrong pet logic vs `careLevel` is a finding).
