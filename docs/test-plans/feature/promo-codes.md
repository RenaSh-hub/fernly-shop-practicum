# Test plan: feature/promo-codes

## Summary

Adds promo codes to the cart: `POST`/`DELETE /api/cart/promo`, cart/order fields `discount` and `promoCode`, percentage and free-shipping codes, and a cart UI (`PromoCodeInput` via the cart-summary slot) that updates `OrderSummary` on cart, checkout, and order pages.

Money and sign-in behaviour are covered first. Cases follow `docs/features/promo-codes.md` and `docs/PRODUCT.md`; the product docs win when they disagree with the code.

## Assumed — ask

1. **Expired copy:** Doc requires a message that the code has *expired*. Exact string and whether unknown vs expired share `promo_invalid` only — confirm expected `detail` text for `SPRING5` vs a gibberish code.
2. **Percent base:** Doc and OpenAPI say percent off **plants only**; confirm tests should assert that (and treat discount-on-shipping as a product bug), not the current `(subtotal + shipping)` implementation.
3. **Label pattern:** Is the visible title “Have a promo code?” enough, or must the text input have a proper `<label>` / `aria-label` naming “Promo code” to match the feature bullet and PRODUCT AA rules?
4. **Live region:** Confirm refused errors must use an assertive/polite live region (or equivalent) for “announced … as soon as it appears,” not only visible text.
5. **Checkout promo editing:** Docs only put the Promo code field on the cart. Confirm checkout/order are display-only for discount (no apply/remove there).
